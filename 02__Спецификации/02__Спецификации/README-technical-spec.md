## 3. ПРАВИЛА ЧТЕНИЯ И ВЫБОРКИ

- Ключ сопоставления позиции во всей экосистеме — `HASH COLLECTION`.
- В выходные документы попадают только `isSHIPPED = "true"` и старшая `VER COLLECTION`.
- Скрытые правки читаются по `isPROCESSING = "true"`.
- **Закрытые поля** (не выносятся во внешние выпуски): `SUPPLIER`, закупочные цены, артикулы, наценки, скидки, `COMMENT WORK`.
- Работа агента со спецификациями — **только на чтение**; файлы OneDrive могут быть заняты Excel-сессией инженера — при ошибке доступа читать копию или отложить.

## 4. КРАТКИЕ КОММЕНТАРИИ ПО ПУНКТАМ РЕЕСТРА

- **Тип 30 (п. 2)** — техническое приложение к договору, без цен; читается инженерным составом.
- **Тип 40 (п. 2)** — коммерческое приложение: цены реализации, НДС 22 %, принцип чистой базы; база строк паспорта заказа — «Итог» этого файла.
- **Регенерация** — выполняется инструментом HorizonBI (ETL) по инициативе инженера; каждый выпуск фиксируется строкой п. 2 с датой. Основание — **Решение № 3 от 03.11.2026** (состав: `L50/master` → возврат `L8050 stand-alone`): протокол `01__Документация\Протоколы\01__преддоговорные переговоры\03__Решение-N3 - преддоговорные переговоры - 03.11.2026.md`; мастер тип 20 обновлён стороной заказчика 05.11.2026; тип 40 перегенерирован 05.11.2026 (конфиг — `40__to_customer_fin\01__DSL-config\`); **тип 30 — ожидает перегенерации**.

## 5. ПОРЯДОК ВЕДЕНИЯ

1. Каждая перегенерация типа 30/40 — новая строка (файл, дата, причина).
2. Изменения состава (решения стороны заказчика) — одновременно в реестре заказов, реестре ТКП и здесь.
3. Корректировки мастера в заказе **не** заводятся — первичный учёт в рамке.
